## 0. 結論

1. **原因（確認済み）**：自チームのパス中に、受け手以外まで守備形へ戻る直接の原因は、`decision.mjs` 42行目の保持判断です。この判断は「見えている保持者がいるか、2.1m以内に味方がいて敵がいない」だけで決まります。パスが2.1mを離れると、全員が `cover|private_shape_and_possession_hypothesis` を選びます。選手自身は、味方の足のキックを目撃した記録（`observedTouch`、part=`foot`）を持っていますが、この判断には使われていません。
2. **候補（隔離・未採用）**：本人が観測した証拠がすべて揃い、相手が1秒以内に球の経路へ届かない場合にかぎり、cover を support に置き換える候補を作りました。必要な証拠は次の4点です。
   - 味方の足のキックを自分で目撃した
   - 球速は、そのキック以降の観測だけから推定されている
   - 球の観測が新しい
   - 球の近くに相手がいない
3. **結果**
   - 狙った陣形は、判断名でも実際の移動でも変わりました。自然試合のパス飛行中、cover の比率は 66.1% → 41.7%、受け手以外の前進速度は 0.56 → 0.93 m/s。
   - **同じ機会で比べると**（2試合・パス888本）、受け手以外だけが書き換わった547本では、パスの直接の結果がほぼ不変でした（変化 3.7%、受け手の制御 286→285、6秒後の保持 267→266）。
   - **受け手本人が書き換わった341本では副作用が出ました**。結果の変化 25%、プレー外 39→60、6秒後の保持 175→156。
4. **判断**：**採用しません。** 本人の観測だけでは「自分が受け手か」を区別できず、区別するには受け手が扱える時間帯（ちゃつぴ側の担当）の情報が要ります。条件を変えて局所調整を重ねることはせず、この反例と原因をもって止めます。受け手以外の陣形という部分は有効性が見えたため、ちゃつぴ側の成果と接続した後に再検証する価値があります（§8）。

## 1. 前提の訂正と定義

| 指標 | 値 | 何を数えたか |
|---|---:|---|
| I17監査の「パス飛行中 cover 57.3%」 | 57.3% | 再開キック、スロー、シュート等を含む全キックの飛行中。判断名の時間比 |
| ちゃつぴ側の再集計（771） | 約60.4% | 通常パス限定。判断名の時間比 |
| 本報告の基準値（OFF 6試合） | **66.1%** | 通常パス（`kind=pass`）限定、**出し手と狙われた受け手を除く**フィールド選手。判断名の時間比 |

- 判断名の比率は、守備位置へ移動した比率ではありません。そこで本報告では、実際の移動（前進速度、キックから最初の接触までの前進量）と、判断の目標点のずれを別に測りました。
  - cover の目標点も、球の x に合わせて前へ動きます（(bp.x−52.5)×0.48）。support との主な差は「約7m深く、球の側へ寄る」点です（同じDTOで比べた中央値：前方 5.1〜5.4m、横 2.2m）。
  - X-2 では、cover のまま 2〜6m 前進していました。
- 監査で示した「support↔cover 18回/分」は、間の別の判断を飛ばし、再開中も含む数字です。直接の切替回数としては使いません。
- 実効設定（全実行で `exportState().config` を記録）：`zonalDefence=false`、`perceptionError=true`、`halfTicks=54000`。エンジンのコンストラクタ既定で `passPrinciples=true`（パスR1の対話・飛行選択が有効）です。I18枝も同じ設定で、変えたのは判断の差替え1点だけです。

## 2. パスを出した後に何が変わるか（同じ本人DTOでの時系列）

`probe_window.mjs` で、各tickについて次を照合しました。判断（本人DTOの要約付き）、適用中の action、速度、実際の位置、キック、接触。詳細は `probe/*_base.json` にあります。

**D-2（771、tick 54772、B08→B10、2.55秒、B10が制御）**
- キック直後（54773）、パス側の全員の DTO に「味方B08の foot キックを目撃」が入る（表中の*）。
- 54773 は出し手が2.1m以内にいるため support。**54777、出し手が2.1mを離れると、B01, B02, B03, B05, B07, B09 が cover へ変わり、飛行中ずっと cover。** 適用中の action も 54780 から cover。
- 実際の移動：キックから最初の接触まで、受け手以外の平均 −0.76m（後退）。受け手B10もキック後0.85秒は cover。出し手B08は1.5秒間、自分のパスに receive していた（球集中という別の課題）。

**X-2（10474、A09→A10、良い連結）**：飛行中も cover のまま、2〜6m前進していました。各選手の観測では、相手が1秒以内に経路へ届きます。

**P-1（590、B10→B08、A07が奪取）**：B側の誰も B10 のキックを目撃した記録がなく（`observedTouch` が更新されない）、証拠がそもそも成立しません。

**I-1 / I-2（相手が奪取する場面）**：奪取前は、判断上の書換えが走る時間があります（§5で、奪取の何秒前に止まるかを測定）。

接触と制御の区別：B10 の `contact control=true` は個人の制御、その後の B10 の dribble は本人の次のプレーです。チームとして攻撃が続いたかは「6秒後の制御チーム」、選手本人の認識は「判断kindと DTOの `observedTouch`」で、それぞれ別に記録しています。

## 3. 攻撃継続を推測できる根拠の検討

- **使えるもの**（本人のDTOにある）
  - `self.observedTouch`：目撃した最新の接触。誰が、どのチームか、どの部位（foot/body/hand）か、いつか。エンジンのコメント「Only witnessed executed touches enter memories. No kick target/intent … copied」のとおり、**キックの意図や狙った相手は含まれない**。
  - `ball.velocityEvidence`：観測差分から推定した球速。いつからいつの観測によるか。接触を目撃すると推定は無効になる。
  - 記憶している人の位置（最大24tick前まで）。
- **使わないもの**：パスの意図や受け手のID、将来の接触、他選手の判断、ちゃつぴ側の受球予測やパス意図の通知。
- **保証しないこと**：パスが出たことは、成功も保持も意味しません。そのため次のどれかに当たれば、主張を取り下げて元の判断へ戻します。
  - **相手の介入**：相手の接触を目撃した、同時接触、球から2.1m以内に相手がいる、記憶している相手の誰かが1秒以内に経路上の点へ届く（相手の能力が分からないため速さ8m/sと保守的に仮定）。
  - **球の方向変化**：キック以降の観測だけで推定した球速であること。接触を目撃すれば推定は無効になる。目撃していない接触による方向変化は、次の観測で推定が更新されて反映される。
  - **情報の古さ**：目撃したキックから2.5秒を超えた、球の観測が2tickより古い、球速 3m/s 未満（ドリブル程度の球は従来の近接判断に任せる）。
- **既知の限界**：目撃していない相手の接触は、推定が更新されるまでの最大1判断周期分（4〜5tick）、見逃し得ます。

## 4. 実装（隔離候補）

- 追加ファイル `i18_flight_shape.mjs`（純関数）：`chooseI18(o)` は元の `choose(o)` を呼び、結果が `cover|private_shape_and_possession_hypothesis` で、かつ証拠が成立したときだけ、kind を `support`、目標を元の `privateSupportTarget(o)` に置き換えます。点数（0.65）は変えません。
- **変えないもの**：球へ向かう判断の点数（press / intercept / receive）、受球、再開、GK、手の処理、CB の advance_support、DM/CM の cover_exchange（いずれも従来の近接判断のまま）。
- 置き換えないものと避けたこと：守備への切替を一律に遅らせる、全員を攻撃位置に固定する。
- 差分：`I18_CODE_DIFF.patch`。`engine.mjs` は1行のimportの差替えのみで、ほかに新規モジュール1つ、保存識別子3つ（save / engine / result）。原本 `source/` は無変更（MANIFEST 2,421件一致を再確認）。
- 枝の生成：`build_i18.py <I17展開先> <出力>`。変更しないモジュールは原本を絶対パスで参照します（I14と同じ方式）。

## 6. 改善・副作用・未検証・未採用

- **改善（確認済み）**：受け手以外の陣形が、自チームのパス中にも攻撃形を保ちます（判断名と実際の移動の両方）。受け手以外だけが書き換わった場合、パスの直接の結果は変わりません。既存の良い連結（X-2）と、証拠のない場面（P-1）は完全一致で守られました。相手が触る1秒以内の主張は 0.5% のみ。
- **副作用（確認済み）**：受け手本人が書き換わると、プレー外が増え（+21/341）、保持が減ります（−19/341）。自然試合でも、スロー・CKの増加とプレー時間の減少（433.2→423.7分）として表れています。
- **影響なし**：前方の選択肢が増えて攻撃の出口になる効果（0.83→0.81）、球集中、奪取時の中央と背後の守備の人数。
- **未検証**：zonal ON との組合せ、CK研究枝との組合せ、陣形や能力の差、Node 24、実機、製品セーブ。ペア比較は2試合・6秒の範囲。
- **未採用**：I18候補のすべて。既定や正本には入れていません。パスR2、未採用のパス原則候補、SOC系も入れていません。

## 7. 反例と原因

R-1（seed 31337、tick 15323、B02→B09）と G-1（771、tick 1257）が反例です。どちらも受け手が「受球へ入る前の cover」の段階で書き換わり、その数tickの経路の違いが受球の成否を分けました。選手本人には「自分が狙われた受け手かどうか」を知る観測がありません。経路の幾何から自分で推定すると、ちゃつぴ側の受球予測・受け手時間帯の研究と重複するため、本作業では追加しませんでした。

## 8. ちゃつぴ側への引渡しと次の最小検証

- 引渡し：`eval/paired_771.json` / `paired_31337.json` の「受け手が書き換わった341本」と「受け手以外のみの547本」の一覧。各本にキックtick、出し手、受け手、結果の対、書き換わった選手を記録しています。再現は、キックtickの save を標準で作り、I18へ移植します（`mkstate.mjs` / `probe_window.mjs`）。
- 次の最小検証（実行していません）：ちゃつぴ側が確定させた「受け手として扱える時間帯」の判定を本人の判断へ渡せるようになった時点で、**その時間帯の対象者を I18 の書換えから外す1条件だけ**を加え、同じ888本のペア比較を再実行します。受け手以外だけの547本の結果（ほぼ中立）が、全体で再現するかを見ます。
- 関連する既存成果：I17監査の課題3（保持判断の揺れ）、課題4（パス→受球）、R2（受球後の意図）、SOC23（outlet attention）、early_ball_intent、ordinary_pass_continuity（出し手の pass の再構成にのみ元の choose を使用。I18は pass を変えないため整合）。
