## 3. 髪の仕上げ

### 材質の構成を変更（透過の描画順・ちらつき対策）

- **元の状態:** FH53 も FACE52 も、cap 全体が半透明でした。three.js では、半透明の glTF 材質は奥行きを記録しないため、描画順で結果が変わります。
- **FH54 の構成:**
  1. **Cap（不透明）:** cap の内側。奥行きを記録します。
  2. **CapEdge（半透明）:** 生え際の細い帯だけ。
  3. **Cards（半透明）:** 毛束。三角形を内側の層から外側の層の順に並べました。
- **見つけた不具合:** Blender 4.2 の glTF 書き出しは、Alpha の端子がつながっていると BLEND として書き出します。初回は不透明にならなかったため、不透明の Cap では Alpha をつながないように修正しました。書き出し後の GLB で `OPAQUE` になっていることを確認しています。

### 生え際の作り方

| 改良 | 内容 |
|---|---|
| 生え際の形 | 少し不規則にしました（0.6〜1.0°） |
| 生え際の帯 | 専用の **生え際テクスチャ** を作りました。毛先が 1 本ずつ途切れるように透過させています。この帯には、生え際に沿う専用の UV を付けました。 |
| 毛束の根元 | 透明になる範囲を 10% から 22% に延ばしました。根元は cap から 0.5mm に密着させ、層の間隔は毛先へ向かって広げます。 |
| めり込み対策の押し出し | 上限を 2.5mm にしました。FH53 では最大 8.7mm まで押し出しており、髪が膨らんで見える原因でした。それでも皮膚に当たる毛束は、先端を 1 区間短くし、テクスチャを縮めて毛先の細さを残しました。 |
| 浮いた細い毛束 | 試作しましたが、肌の上に黒い点が浮いて見えたため採用しませんでした |

## 4. 組み合わせ・動作・表示の検証

### 4.1 顔 4 × 髪 5 ＝ 20組（`QA_TABLES54.md` §1）

| 区分 | 髪×皮膚 | cap×カード | カード同士 | cap の外の皮膚点 | 頭蓋の穴の上で半透明の頂点 |
|---|---|---|---|---|---|
| **H0 原本 4組**（対照） | F0 51、F1〜F3 46（FH53 では 64） | 0 | 7 | 0 | 134 |
| **新しい髪 H1〜H4 16組** | **すべて 0** | H1 20、H2 0、H3 0、H4 68 | H1 208、H2 19、H3 225、H4 384 | 0 | 0 |

- **cap×カードの内訳:** 多くは毛束の根元の透明な部分（例: H4 では 13 三角形中 12）か、生え際の帯との接触です。髪の部品同士の接触です。
- **FH53 との違い:** FH53 では、毛束を最大 8.7mm 押し出して交差を 0 にしていました。FH54 は髪を膨らませないことを優先し、押し出しを 2.5mm までに抑えたため、この数が残っています。
- **カード同士の交差:** 毛束の重なりと、毛の流れが集まる場所で起きています。FH53 とほぼ同じ数で、減らせていません。

### 4.2 透過の描画順とちらつき（ブラウザ）

- **環境:** three.js 0.186.1、ヘッドレス Chromium、SwiftShader によるソフトウェア描画。
- **描画順を最悪に強制した試験:** 毛束を他の半透明の髪の部品より先に描画させ、通常との差を測りました（`M10`）。

| モデル | 変化した頭部画素の割合 |
|---|---|
| FACE52 | 1.0〜2.2% |
| FH53 | 最大 5.4%（H1）、6.7%（H4） |
| FH54 | 最大 0.16%（H1）、0.22%（H4）、H2・H3 は 0% |

- **仰角 −20〜85° の撮影:** three.js の標準の並べ替えでは、描画順は一度も変わりませんでした。物体ごとの中心で並べ替えるエンジンを模した方式では 1 回入れ替わりましたが、画像の変化はほぼありませんでした（0.01% 以下）。
- **ちらつき:** 120 コマの周回で、正しい奥行きの参照画像との差がコマ間で急に跳ねる箇所はありませんでした（2 以上の跳ねは 0 コマ）。
- **注意:** 髪色が黒に近いため、描画順の違いが見えにくい条件です。明るい髪色では未検証です。

### 4.4 Reference04 の既存動作での首の確認（`M09`、`QA_TABLES54.md` §6）

- **使った動作:** `REF_gamemtn0_id0001 / id0039 / id1012_normalized_phase` の 3 本です。元の fps は不明で、各 61 コマを 1.0 秒として正規化されたものです。動作の意味や速度は推測していません。
- **方式:**
  - (A) 固定: 頭を首のボーン REF_joint_20 に親子付けしました。
  - (B) ウェイト転写: 首の下側の頂点に、最も近い胴体の頂点のウェイトを写し、上へ行くほど REF_joint_20 の 100% に移しました。
  - どちらも **レビュー用の仮の接続** で、本番の接合ではありません。

| 動作 | 首に対する頭の回転 | 固定 | ウェイト転写 |
|---|---|---|---|
| 静止 | — | 1.35mm | 1.35mm |
| id0001 | 0.9° | 1.47mm | 1.35mm |
| id0039 | 7.5° | **12.1mm** | 1.45mm |
| id1012 | 19.8° | **14.3mm** | 4.52mm |

- **結論:** 頭を固定するだけでは、首を回すと継ぎ目が開きます。首のウェイトを写すと大きく減りますが、最も大きく回る動作では 4.5mm 残ります。
- **残る問題:** 頭と胴体の首で肌の色に差があります。

## 6. 未検証・既知の不具合

1. カード同士の交差が多い（H1 208、H3 225、H4 384 対）。明るい髪色での描画順の影響は未検証です。
2. H1 の耳の上の毛先、H3 の前の縁、H4 の上から見た毛束、H2 の前の生え際のなめらかさ（§3）。
3. 顔が F0 だと耳は原本のままで、短い髪型では尖って見えます。F1〜F3 の耳は改善しましたが、作り直してはいません（UV が最大 0.56 倍に縮む）。
4. F2 と胴体の肌色の差。胴体の肌色は変えていません。
5. 描き直した眉は、元の写真の眉より平らに見えます。拡大すると描いた線だとわかります。
6. 首の接合はレビュー用の仮の接続だけです。本番のウェイトと縫合はしていません。最大の回転で 4.5mm の隙間があります。
7. 未検証: iPhone 実機、実際の試合エンジン、GPU での性能、LOD、明るい髪色の透過、第三者による見た目の確認、Blender 4.0.2。
