# Q30：到達可能な受球計画があるのに、点数が「現在の球との距離」で下がって受球に向かわない局面

I17 標準（`integration_i8_standard`）のコードと、手元の記録（Q27・Q29 系列の再演、7場面スイート、Q29F の長い基準走行）を使いました。

- 原本・AI・正式採否は変更していません。候補コードは受け取っていないので、候補の再現・評価はしていません。§3 の数値は、記録された観測に点数式を当て直した仮の計算で、動作の変更ではありません。
- 判断行の件数は、同じ場面の連続判断や同じ試合の別窓を含み、独立したプレー数や頻度ではありません。
- 未取得の資料：ちゃつぴ側の受球候補コード、全試合（90分）の記録、L21 研究の受球 V2 の改善例の保存。

記号：DP＝専用の受球計画を使った判断、汎用＝計画なしで汎用探索の点を使った判断。20 tick/秒。

## 0. 要点

1. **コード上の事実：** 受球の点数は現在の球との距離・相手を押す強さ・観測の古さ・自チーム保持の罰・自分より球に近い味方の数で決まり、**専用の受球計画の有無も、計画の到達点までの距離も入っていません**。計画は点数の後に目標を置き換えるだけです（`decision.mjs:50-62`）。
2. **そのような局面はあります。** 基準の判断 102,605 行のうち、エンジン自身の入口（canPlay でない・保持者が見えない・相手の保持でない）を通って計画が成立した行は 1,649 行、そのうち receive／intercept 以外が選ばれた行は **221 行（124 区間）**でした。
   - 点数で負けた相手は cover 160・support 46・advance_support 14・cover_exchange 1。
   - 原因の内訳（区間）：自チーム保持の罰（−1.5）37、距離と「前にいる味方」の罰 87。
   - 多くは短い遅れです。最初の計画行から receive を選ぶまでの遅れは中央値 8 tick（2 判断、0.4 秒）、最小 4 tick。64 区間は結局本人が触れました。
3. **改善候補の例（本人が宛先、罰なし、結果は相手）：** 10 区間。4 件を追跡しました（§2.2）。共通の形は「パス直後、16〜19 m で計画が成立（到達点まで 1.3〜7 m）、cover が 0.01〜0.17 点差で勝つ → 1〜2 判断後に receive → 球は 1.4〜1.8 m を通過 → 相手が回収」です。
   - **断定しないこと：** 早く receive を選んでいれば受けられたかは確認できません。A・C では receive に切り替えた後も計画は消えて汎用の追走になっており（Q29B の「近い目標で制動して球の後ろを追う」形）、取りこぼしの直接の原因は点数だけではありません。
4. **別行動が妥当な例：** 自チーム保持の罰で support になる例（O3 の A09：1 m 先で味方 A07 がドリブル中）と、より近い味方がパスを受ける例（60914 の A01：23 m、前に味方5人、パスは A09 へ）。どちらも receive に向かわないのが妥当と読めます。
5. **計画の到達点までの距離を点数に使った場合（仮の計算）：** 221 行のうち 160 行で receive が勝ちます。その後の結果は、本人が触れた 109、相手 32、味方 10、なし 9。副作用は §3 のとおりで、特に「遠くからの楽観的な計画（eta 1.5 秒、最高速前提）で守備の形を崩す」「計画が消えた後の追走は変わらない」の2点です。
6. **次の最小検証（§4）：** 候補コードを受け取ったうえで、改善候補 A〜D と妥当例 2 件、Q29 の対照（O2・N5 の利益、N1・N2 の正常）を同じ開始状態から短窓で比べ、「最初の receive の時刻」「その時点で計画があったか」「最接近」「次のプレー」を事前に固定した指標で記録する。

## 1. コードの確認（事実）

### 1.1 判断時点で本人が使える情報（`perception.mjs:16-19`）
- 自分：位置・速度・向き・能力・直前の自己接触（`touch`）・最後に目撃した接触（`observedTouch`）。
- 球：見えていれば現在の観測、見えなければ最大 24 tick 前までの記憶。速度は観測の差分から推定（`velocityKnown`）。
- 他の選手：見えている人は現在の観測、見えない人は 24 tick 以内の記憶。`holding`（GK が持っているか）だけ公開。
- コーチの枠（press 0.5 など）。
- 出し手の意図・宛先、未来の真値は入りません。宛先（`targetId`）はキックのイベントにだけあり、受け手には渡りません。

### 1.2 専用の受球計画の成立条件（`reception.mjs:11-18, 38`）
球が低く（z < 0.5）、GK でなく、速度既知、観測が 0.25 秒以内、球速 > 3 m/s、最接近が未来かつ 1.5 秒以内、最接近点に最高速で届く、そして 0.1〜1.5 秒先の飛行点のどれかに身体予測（`estimatedArrival`：現在速度・加減速・0.1 秒の遅れ込み）で 0.8 m 以内に寄れること。

### 1.3 点数（`decision.mjs:59-62`）
```
receive/intercept の点数 = 1.65 − 0.048×(現在の球との距離) + 0.35×press − (自チーム保持なら 1.5) − 0.4×観測の古さ − 0.22×min(2, 自分より球に 2 m 以上近い味方の数)
cover / support = 0.65、advance_support = 0.55+0.6×cbAdvance（CB、相手が 9 m 以内にいない）、cover_exchange = 0.92（DM/CM）
```
- press 0.5、古さ 0 なら基礎は 1.825。距離だけで 0.65 を下回るのは **24.5 m**、前の味方 1 人で 19.9 m、2 人で 15.3 m。自チーム保持（味方が球の 2.1 m 以内、相手なし）なら、距離に関係なく receive は負けます。
- 計画は `receptionPlan(o)` で先に計算されますが、点数には使われず、**目標と eta を置き換えるだけ**です。
- `chooseReceptionProposal`（保持の罰を「受球の証拠」で免除する版）は存在しますが、標準ではゾーン守備経路からしか呼ばれず、記録ではゾーン守備は無効です。

### 1.4 判断→適用の遅延
判断は 2 tick 後に適用、次の判断は 4〜5 tick 後（`engine.mjs:149, 207`）。点数で負けた判断は、次の判断まで 0.2〜0.25 秒、別行動を続けます。

## 3. 計画の到達点までの距離を点数に使った場合（整理。候補の実装・評価ではない）

**仮の計算：** 221 行で、距離の項を「現在の球との距離」から「計画の到達点までの距離」に置き換えると（他の項はそのまま）、160 行で receive が勝ちます。計画の到達点は 0〜9 m 先なので、距離の罰がほぼ消えるためです。残り 61 行は保持の罰（−1.5）で変わりません。

| 利点として期待できること | 根拠 |
|---|---|
| 計画が成立した瞬間に commit できる（0.2〜0.5 秒早い） | 124 区間の遅れの中央値 8 tick。A〜D |
| 計画は本人の観測と身体予測だけで作られるので、情報の境界は変わらない | §1.2 |
| 同じ tick に同じチームで複数が flip する例は、221 行ではなかった | `eval/hypothetical_flip_stats.txt` |

| 副作用として起こり得ること | 根拠 |
|---|---|
| 遠くからの楽観的な計画で commit する。計画は eta 1.5 秒・最高速前提で、16〜25 m からでも成立する（A〜D は 16〜19 m、外れ 0.76 の限界例 D も含む） | §2.2、計画の入口 |
| cover を離れて守備の形が崩れる。160 行の多くは cover が勝っていた行 | 内訳 |
| 前の味方の罰（−0.22×人数）は残るが、距離の項が消えると 2 人分でも打ち消せない。複数の味方が同じ球に向かう余地が増える | 式 |
| 計画が消えた後の汎用の追走（制動して球の後ろに回る）は変わらない。早く commit しても A・C 型の通過は残り得る | Q29B、§2.2 |
| 保持の罰で負ける 61 行は変わらない（妥当な場合が多い） | §2.3 |
| 受球 V2（保留中）や飛行時間連動（Astra）と作用が重なる。別々に検証する必要がある | Q29 |

**未取得：** ちゃつぴ側の候補コード。ここでの数値は記録された観測に式を当て直した仮の計算で、動作（身体・接触・相手の反応）は含みません。

## 4. 次の最小検証（候補コードを受け取ってから）

1. **事前登録：** 指標を先に固定する。各鍵のパスについて、宛先の最初の receive 判断の tick、その時点で計画があったか、計画の外れ・eta、最接近、次のプレー、相手の最初の介入。良し悪しは判定しない。
2. **同じ開始状態：** 改善候補 A（26340）、B（81235）、C（80130）、D（43975）、妥当例 O3（12340）、A01（60900）を基準の経過から `fromFixture` で渡す。候補の名札・witness の拒否は回避しない。
3. **対照：** O2・N5（V2 の利益）、N1・N2（正常）を同じ手順で走らせ、変化しないことを確かめる。
4. **分ける：** 「早く commit したか」と「受けられたか」を別に記録する。A・C 型（計画が消えて汎用になる）では、点数の変更だけでは変わらない見込みを先に書いておく。
5. **やらないこと：** 90 分試合、係数の調整、受球 V2・飛行時間連動との同時変更。
