# Q29 追補：受球V2がドリブラー自身の次タッチに先に作用した理由

Q29 で、受球V2が作用した4機会（O1・O2・O3・O4）はいずれも、鍵のパスより前に「ドリブル中の選手が自分で押し出した球」への判断から分かれていました。ここでは、その4件を判断→動作→接触／キック→パス時刻の順に追い、なぜ起きたかをコードと保存記録から切り分けます。

- 原本・AI・正式採否は変更していません。新しい実行はなく、Q29 の20条件の記録（同じ開始状態、全フレーム・全行が参照と一致済み）を読み取り専用で解析しました。
- 出し手の飛行時間案との作用は混同しません。各機会で、基準＝飛行時間版、V2＝両方版のフレームが「パスのキックまで同一」であることを先に確かめています。
- 60288 の長い先読みは、球外の原因と断定しません（Q29 本文 §4.3(c)・§6 のまま）。

記号：DP＝専用の受球計画を使った／FE t＝汎用探索で t 秒の点が到達可能／EX＝2秒先の末尾点／VU＝球速不明。時刻は 20 tick/秒、判断は 2 tick 後に適用されます。

## 0. 要点

1. **事実：V2 と I17 の受球計画の違いは、コード上は「最接近がすでに過去（tClosest ≤ 0）の球を対象に含めるかどうか」だけです。**
   - I17：`if(tClosest<=0||tClosest>1.5)return null;`
   - V2：`tClosest>1.5` だけで除外し、`tClosest<=0` のときは最良候補の外れが 0.49m 以下、相対速度が閾値以下なら計画を返す。
   - 保存済みの全判断 DTO 15,104 件（球を観測しているもの）に純関数として当てると、`choose` の結果が違ったのは 81 件で、**81 件すべてが tClosest ≤ 0、I17 は計画なし・V2 は計画あり、種類は両方とも receive** でした。tClosest > 0 で違った例は 0 件です。
2. **事実：その 81 件のうち 54 件は、直前のキックが本人のドリブルでした。** 残り 27 件は他人のドリブル（23）か他人のパス（4）の後です。77 件は球まで 2.5m 以内、81 件すべてが球速 3〜6 m/s でした。
   - ドリブル中の選手が押し出した球は、「本人の 1〜2m 前を同じ向きに 3〜5 m/s で転がる」ため、本人から見れば最接近は常に過去です。これが V2 の変更点にちょうど当たります。
3. **事実：4機会とも、最初の作用は同じ形でした。**
   - 基準（I17）は汎用探索の最初の到達可能点（t = 0.1〜0.3 秒、本人から 1.4〜2.7m）を目標にします。この近い目標に対して操舵の制動が効き、希望速度は 3.8〜5.4 m/s に抑えられ、選手は球の 1.0〜1.9m 後ろを**追走し続け**、球が摩擦で 3 m/s 以下に落ちるか 1.0m 以内に入るまで触れません。
   - V2 は球の飛行点（eta 0.8〜1.05 秒、本人から 4.4〜6.2m）を目標にします。制動が効かず希望速度は最高速（6.5〜7.1 m/s）になり、選手は加速して球に追いつき（0.4〜0.6 秒で 1.0m 以内）、そこで出口の候補（パス／ドリブル）を選びます。
4. **事実：この差が、次のタッチとパスの時刻を動かしました。**

   | 機会 | 選手 | V2 の最初の作用（判断→適用） | 次のタッチ：基準 → V2 | 鍵のパス：基準 → V2 |
   |---|---|---|---|---|
   | O1 | A05 | 42160→42162 | 42190 パス → **42170 パス**（20 tick 早い） | 42190 A05→A10 → 42170 A05→A10 |
   | O3 | A07 | 12341→12343 | 12367 パス → **12355 パス**（12 tick 早い） | 12367 A07→A09 → 12355 A07→A09 |
   | O4 | B09（相手） | 60049→60051 | 60083 ドリブル → **60056 ドリブル**（27 tick 早い） | （A の宛先つきパスは V2 では起きない） |
   | O2 | A09 | 42316→42318（鍵のパスの後） | 42330 ドリブル → **42323 ドリブル**（7 tick 早い） | ― |

   - O1・O3 では、早まったパスは**出口の候補の点数で選ばれた**ものです（O1：pass→A10 1.19 > dribble 0.89、O3：pass→A09 1.18 > dribble 1.04）。基準では同じ選手が、球が減速して 1.0m 以内に入るのを待ってから、早期の球行動（EBI）でパスを出しています。
   - O4 の V2 では、早まった 60056 のドリブルが、空いている側（タッチライン側）へ向きました。その球は 60083 にタッチラインを越え、A のスローインになりました。基準の 60083 のドリブルは前方へ向き、場内に残りました。向きの違いは、タッチした時点の位置と相手の配置が違うためで、ドリブルの方向候補がタッチラインを考えない I17 の性質によるものです。V2 の欠陥とも自然なミスとも断定しません。
5. **事実：出し手の飛行時間案はこの段階に関与していません。** 4機会とも、基準と飛行時間版は鍵のパスのキックまでフレームが同一、V2 と両方版も V2 の（早まった）パスのキックまで同一でした（O4 は 400 tick すべて同一）。
6. **推測：** V2 の作者が意図したのは、受け手に向かって来た球が目の前を通り過ぎた直後の回収だと思われます。しかし条件は「最接近が過去」であれば満たされるので、同じ条件に当てはまる「自分で押し出した球」にも効きます。意図かどうかはコードのコメントからは読めず、**未確定**です。
7. **未検証：** 早いタッチが良いのか悪いのか（サッカーの評価）、全試合での頻度、V2 を「本人の最後のタッチが自分」の場合に限ったときの振る舞い。いずれも今回の範囲外です。

## 1. コード上の違い（事実）

`reception.mjs` の差分（V2 base_on vs I17）は3か所です。import の書き方は除きます。

| 行 | I17 | V2 |
|---|---|---|
| 17 | `if(tClosest<=0‖tClosest>1.5)return null;` | `if(tClosest>1.5)return null;` |
| 18 | 最接近点に届かなければ null | `tClosest>0` のときだけ同じ判定 |
| 39 | （なし） | `if(tClosest<=0&&(best.miss>.49‖best.relative>threshold))return null;` |

候補のコスト（両版共通）は `max(0, miss−0.49)×8 ＋ max(0, relative−(threshold−0.45))×2 ＋ t×0.1 ＋ 向きの罰` です。

- `miss ≤ 0.49` の範囲ではコストが平らなので、最良候補の miss は 0.49 のすぐ下に集まります。今回の 81 件の miss は 0.42〜0.488（中央値 0.465）、0.49 を超えた例は 0 件です。
- `threshold = 3 + control×0.11` は 10〜11 m/s です。3〜6 m/s の球では相対速度の条件は常に満たされます（81 件の最大 2.40 m/s）。
- したがって、押し出された球に対して V2 の新しい関門は実質的に効かず、**「最接近が過去でも計画を出す」という変更がそのまま現れます**。

判断側（`decision.mjs:52`）は両版同じです。`receptionPlan` が呼ばれるのは `!canPlay && !visibleHolder && !theirPossession` のときだけで、計画があれば汎用探索の点を上書きします。種類は球速 > 3 なら receive です（両版同じ）。

## 3. なぜ「ドリブラー」に先に効くのか（切り分け）

**事実（全 DTO の分類、`eval/v2_where_differs.json`）**

| 項目 | 件数 |
|---|---:|
| 球を観測している判断 DTO | 15,104 |
| 受球計画（純関数）が違う | 174 |
| `choose` の結果が違う | 81 |
| そのうち tClosest ≤ 0 | 81（100%） |
| そのうち I17 は計画なし・V2 は計画あり | 81（100%） |
| そのうち直前のキックが本人のドリブル | 54 |
| 直前のキックが他人のドリブル／他人のパス | 23／4 |
| 球まで 2.5m 以内 | 77 |
| 球速 3〜6 m/s | 81 |

- 計画が違う 174 件のうち 93 件は、`choose` の結果には現れません。canPlay（自分で蹴れる）か相手の保持（press）か、ほかの理由で計画が呼ばれない判断です。O1 の 42156、O4 の 60041 がその例です。
- 他人のキックの後の 27 件は、味方や相手が押し出した球が自分の横を過ぎた直後の判断で、記録上は押し出した本人より少数でした。パスの受け手で `choose` が違った例は、Q29 本文のとおり 0 件です。

**推論**

- 「最接近が過去」「3〜6 m/s」「2.5m 以内」「本人の直前のキックがドリブル」という組合せは、ドリブル中の選手が押し出した球そのものです。ドリブルは 7 tick ごと程度に繰り返されるので、この状態は試合中に頻繁に現れます。パスの受け手が球の前に出る状況（tClosest > 0）では V2 は I17 と同じなので、V2 の違いが最初に現れるのは、ほぼ必然的に球を持つ選手自身の次のタッチになります。
- I17 の `tClosest<=0 → null` は、「通り過ぎた球には専用計画を出さず、汎用の追走に任せる」という扱いです。ゾーン守備の `recedingRecovery` のコメント（「0.1 秒先の末尾点では遠ざかる球の横で制動してしまう」）から、作者はこの追走の遅さを認識し、守備の回収に限って別の処理を入れていたと読めます（Q28 §2.5 と同じ根拠）。V2 がこれを一般に外したのは、その延長と読めますが、意図の記述はありません。
- V2 の動作は「追走が遅い」問題に対しては確かに追いつきを早めます。ただし早く触った後の出口（パス／ドリブルの候補の点数、ドリブルの向き）は I17 のままなので、その先の良し悪しは V2 だけでは決まりません。O3（球外）・O4（球外）・O1（受球成功）は、どれもその後の出口と相手の対応で分かれています。

## 5. 事実・推測・未検証

**事実**
- コードの差分（§1）と、純関数での 81 件の分類（§3）。
- 4機会の判断→動作→タッチ→パス時刻（§2）。希望速度は記録された能力と目標距離から計算。
- 基準／飛行時間、V2／両方版のフレームの一致範囲（§4）。
- O4 の 60056 のドリブルの向きと球外。キック誤差が小さいこと。

**推測**
- V2 の変更がドリブラーに最初に効くのは、条件がその状態に当てはまるため（構造からの推論）。
- V2 の作者の意図は「通り過ぎた球の回収」で、自分の押し出した球への適用は副次的（コメントがなく未確定）。
- 早いタッチの後の結果は、出口の候補と相手で決まる（4件からの推論）。

**未検証**
- 全試合での頻度と、早いタッチの良し悪し（Astra の評価、Sol の集計）。
- 「直前のタッチが自分」の場合に V2 を適用しない変種の振る舞い。候補は作っていません。
- Node 24 での再現（今回は v22.23.4）。
