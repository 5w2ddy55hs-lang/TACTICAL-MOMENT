# Q29C 事前登録（候補を走らせる前に固定）

## 登録時点で確認済みのこと（現行と V2 の動き）

- Q29B：V2 と I17 の受球計画の差は「最接近が過去（tClosest ≤ 0）の球を対象に含めるか」だけ。保存 DTO 15,104 件で `choose` が違う 81 件は全件この場合で、54 件は本人の直前のドリブルの後。
- `eval/own_touch_episodes_v2.txt`：V2 の5機会の記録で、「V2 だけの計画」が本人の直前のタッチの後に出た区間は 6 つ（O1 A05、O2 A09×3、O3 A07、O4 B09）。O5 にはない。
  - 次のプレーまで追った結果：O1 → 早いパス → 相手が制御（基準も相手。時刻が違う）、O3 → 早いパス → 球外（基準は受球成功）、O4 → 早いドリブル → 球外（基準はドリブル継続）、O2 → ドリブル継続（基準も継続）。
  - V2 単独の記録で、早いタッチが次のプレーを基準より良くした例は、この5機会にはない。
- 候補の結果はまだ見ていない。

## 候補（v2x）：本人が最後に目撃したタッチが自分なら、V2 の拡張を使わない

- 変更は V2 の `reception.mjs` に1行だけ。tClosest を求めた直後に、  
  `if(tClosest<=0 && 本人の observedTouch の全員が自分) return null;`  
  を入れる。それ以外（最接近が未来、または最後に目撃したタッチが他人）は V2 のまま。
- 使う情報は本人の観測 DTO の `self.observedTouch`（本人が目撃した最新のタッチ：誰・チーム・部位。K20 でも使った欄）だけ。未来や世界真値は使わない。
- 候補を作る理由：
  1. V2 の差が現れた 81 件のうち 54 件が、本人が押し出した球への判断だった（Q29B）。
  2. I17 はその場面を「専用計画なし・汎用の追走」と扱っていた。V2 の拡張が狙うのは、他人の球が目の前を通り過ぎた直後の回収と読めるが、押し出した球にも同じ条件で効く。
  3. 両者を分けて、受け手側（他人の球）への V2 の作用を保ったまま、自分の球への作用だけを外した場合の動きを見る。
- 良い結果に合わせた個別例外ではない。条件は場面・選手・tick に依存しない一般則で、観測できる自分のタッチだけで決まる。
- 独自の名札を付ける。保存の拒否は回避しない。

## 比較条件

- 3条件：基準（base_off）／V2（base_on）／v2x。出し手はすべて基準（I17 の 0.35 秒）。飛行時間案とは組み合わせない。
- 開始状態：Q29 と同じ5つ（42130、42187、12340、60000、飛行時間版の経過 60269）。各版が `fromFixture` で受け付けること、内部状態の一致、保存→復元 20 tick の一致を確認する。
- 構成の確認（結果を見る前）：
  - C1：v2x と V2 の差分がその1行と名札だけ。
  - C2：全保存 DTO に純関数として当て、「最後に目撃したタッチが自分 かつ tClosest ≤ 0」では v2x ＝ I17、それ以外では v2x ＝ V2 であること。`choose` が V2 と違う 81 件のうち、v2x でも違いが残る件数（他人の球の後の 27 件が残る見込み）を記録する。
- 記録と比べ方：
  - 各機会で、基準 vs v2x、V2 vs v2x の最初の差（判断の種類か目標）。
  - 本人の直前のタッチの後の区間ごとに：タッチの時刻、出口の候補、味方と相手の距離、次のイベント、結果の区分（本人／味方／相手／球外／再開／窓内なし）。
  - V2 が他人の球に作用した区間があれば、それが v2x でも残っているか（受け手への作用を失っていないか）。

## 判定しないこと

- 別の展開を自動的に悪化としない。相手の妥当な対応、自然なミスは欠陥にしない。
- 5機会・6区間は関連した少数で、同じ場面の別版も含む。独立したプレー数や発生頻度とは扱わない。
- 60288 は長い先読みだけを原因と決めない（Q29 §4.3(c)）。
- Q28 の2秒先の点を原因と決めない。
- サッカーとしての良し悪し（Astra）と集計（Sol）はしない。

## しないこと

原本の上書き、正式統合、採否の変更、90分試合、新しい係数。
