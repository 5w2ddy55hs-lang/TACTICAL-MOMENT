### 両方版の作り方

飛行時間版のコピーに対して、変えたのは次の4点だけです。

1. `core/reception_v2.mjs` を追加した。V2 の `reception.mjs` と同じ中身で、import の書き方だけを直した。
2. `core/decision_v2.mjs` を追加した。飛行時間版の `decision.mjs` と同じ中身で、reception の import 先だけを変えた。
3. `core/engine.mjs` の decision の import 1行を変えた。
4. `core/pass_build_identity.mjs` に、独自の研究用の名札を付けた。

配線は既存の2版の和集合にしています。

- 受け手の要因は、V2 版と同じく、エンジンの判断経路だけに入れる。OPC1 などの他のモジュールは各ツリーの元の decision を使う。
- 出し手の要因は、飛行時間版と同じくツリー全体に入れる。
- 名札は他の版と違うので、他の版の保存は直接読めず、他の版にも読ませません。
- witness の検査は外していません。

## 何を記録して比べるか（固定）

1. **最初の差**：要因ごとに、最初に違う判断（tick、選手、種類、目標、理由）と、最初に違うフレームを調べる。
   - 出し手の要因：飛行時間 vs 基準、両方 vs V2
   - 受け手の要因：V2 vs 基準、両方 vs 飛行時間
2. **鍵になるパスの追跡**（各機会の、窓内の宛先つきパス）を、判断→適用→受け手の運動→相手→次のプレーの順に記録する。
   - 判断：出し手の判断 tick、適用 tick、キック tick、宛先、先読み、パスの長さと球速
   - 受け手：最初の receive 判断（tick と区分。DP／FE／EX／VU、および V2 の計画かどうか）、速さの最小値、真の最接近
   - 相手と次のプレー：最初の接触（誰、どのチーム、制御したか）、次のキック、球外や再開
3. **結果の区分**（記述だけ）：受け手が制御／味方が制御／相手が先に触る／球外／窓内では接触なし。
4. **作用の分け方**：
   - 「受け手の要因の作用」は、出し手が基準のときと飛行時間のときで別々に書く。
   - 「出し手の要因の作用」は、受け手が基準のときと V2 のときで別々に書く。
   - 二つが違う場合だけ、組合せの作用（交互作用）と呼ぶ。
   - 両方版だけを見て原因を決めない。

## 判定しないこと

- 別の展開になったことを、自動的に悪化とはしない。
- 相手の妥当な対応、自然な miscontrol は欠陥としない。
- Q28 の2秒先の点を、失敗の原因と決めつけない。
- 汎用到達判定と身体予測の食い違いを、受球失敗率とは呼ばない。
- 5つの機会は関連しているので、率や合否にまとめない。
- 鍵のパスの後の最初の保持より先は、記録するが評価しない（サッカーとしての評価は Astra、集計は Sol の担当）。

## しないこと

原本の上書き、正式統合、採否の変更、90分試合、新しい係数や規則の追加。
